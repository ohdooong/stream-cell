## Use Case 1

1. Pipeline 생성
   - `POST /api/v1/platform/pipeline/pipelines`

2. CUSTOM_JAR 파일 업로드
   - `POST /api/v1/platform/pipeline/pipelines/{pipelineId}/custom-jar`

3. 업로드한 JAR 파일 Flink 배포
   - `POST /api/v1/platform/pipeline/pipelines/deployment/{pipelineId}/deploy`

여기서 3번에서 실패할 때.. 어떻게 처리할 것인가? 다시배포가 가능한가?
다시배포는 가능하다.

오류난 jar파일을 올렸을때, 사용자가 jar파일을 다시 올리는것이 가능해야한다.
   - 추후 개발예정

현재는 jar파일을 업로드할 시 중복된 customJobConfig, artifact가 있다고 하며 에러발생.

- pipeline의 job 상태를 동기화하기위해 `PUT /api/v1/platform/pipeline/pipelines/{pipelineId}/status` 호출 시 유효하지 않은 jobId 에러 발생

- flink jar run에 실패했을땐 당연히 flinkJobId 생성도 되지 않는다.

## AI_SQL MVP 범위

### Source
- Kafka Topic 1개
- JSON Format
- StreamCell에 Schema 등록된 Topic
- Event Time Field 필수

### Window
- `TUMBLE`
- 우선 `MINUTE` 단위

예:
```
1분
5분
10분
```

### Group By
- 1~3개 Field

### Aggregation
- `COUNT`
- `SUM`
- `AVG`
- `MIN`
- `MAX`

### Filter
우선 단순비교만 지원.
```
=
!=
>
>=
<
<=
```
